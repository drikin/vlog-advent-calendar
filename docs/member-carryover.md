# 月替わりのメンバー引き継ぎ

## 再現結果

2026-10-04 に公開 API を確認したところ、`2026-09` は13人、`2026-10` は10人だった。
10月から欠落していたのは次の3チャンネル。

- `@dmp2205`（だめぽ）
- `@watarunishida2nd791`（Wataru Nishida 西田航 2nd）
- `@akichannel629`（貧乏小説あきvlog）

従来の `getMembers` は9月までしか継続メンバーを指定せず、10月以降は6月用の
`DEFAULT_CHANNELS` に戻っていた。さらに `page.tsx` が未来月を含む全月を読むため、
未設定の未来月にも、その時点の古いデフォルトが Redis に自動保存されていた。
その後デフォルトを更新しても、保存済みデータが優先されるため回復しない。

## 修正後の動作

- 対象月に保存済み名簿があれば、それを優先する（空配列も有効）。
- 未設定なら直前の月へ遡って名簿を引き継ぐ。名簿の変更点である7月には
  `JULY_DEFAULT_CHANNELS` を適用し、6月の名簿で上書きしない。
- Redis が利用できない場合も、直近の月別デフォルトを使用する。
- 読み取りでは Redis に書き込まない。未来月の先読みで名簿を固定しない。
- 明示的な初期化も同じ継承規則を使用し、同時に保存された名簿は上書きしない。
- 管理者リセットでも共通のデフォルト解決関数を使用する。

## デプロイ時の既存データ復旧（運用者による一度限りの作業）

**コードのデプロイだけでは、既に保存された誤った名簿は変更されない。**
旧実装は自動保存と管理者による変更を区別する情報を残していないため、
保存済み名簿を自動でマージすると意図的な脱退まで取り消す可能性がある。

1. 修正版をデプロイする。
2. Redis 管理画面で `members:2026-09` と `members:2026-10` ～ `members:2026-12`
   の存在・内容を確認し、存在するキーの値をそれぞれバックアップする。
3. 9月の名簿が正しいこと、後続月に意図的な変更がないことを確認する。
4. 後続月のうち、旧実装が保存した誤った名簿と確認できたキーだけを削除する。
   これにより修正版が直前の名簿を引き継ぐ。意図的な変更のある月は維持し、
   必要なら既存のオーナー認証付き `POST /api/members` で個別に修正する。
5. `GET /api/members?month=2026-10` ～ `2026-12` とカレンダー画面で、
   期待するメンバーが表示されることを確認する。

復旧を取り消す場合は、バックアップした値を同じキーへ復元する。
この変更の作成・テストでは本番 Redis の削除や名簿の更新は実施していない。

## ローカル検証

```sh
npm ci
node --test tests/members.test.mjs
npm run lint
npm run build
```

回帰テストは実際の TypeScript モジュールを読み込み、Redis の境界だけを
メモリ上の実装に置き換える。本番の認証情報や外部サービスは不要。
